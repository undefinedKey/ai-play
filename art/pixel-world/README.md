# Pixelbolt 像素素材

本目录保存可编辑配方；`public/pixel-world` 是随项目发布的 PNG 图集、atlas 和前端 manifest。服务运行时只发送静态文件，不启动 Pixelbolt，也不在服务器实时生成图像。

生成工具是 [Pixelbolt](https://github.com/skulitom/Pixelbolt)，固定提交 `ce12f75cc524e63e90d4bd183aecc3a46a6b44ee`。需要 Node.js 22：

```sh
git clone https://github.com/skulitom/Pixelbolt.git data/tools/Pixelbolt
git -C data/tools/Pixelbolt checkout ce12f75cc524e63e90d4bd183aecc3a46a6b44ee
node scripts/build-pixel-world.mjs --inspect
```

已有另一份工具时可设置 `PIXELBOLT_ROOT`。脚本实际调用官方 CLI `validate`、`render`、`inspect`；篝火先调用 `compile`。每次渲染保留独立输出目录，尺寸、图集帧数和工具导出检查失败时立即停止。`--only=wanderer_3 --inspect` 可复查单个资产，最终完整构建才能更新 manifest。

美术原点、调色板与动作意图见 [brief.md](brief.md)。人物、地图、怪物、农作物和装备由本项目原创绘制，没有复制桌宠角色。八种人物基底结合服务端持久化配饰/识别色分配身份；角色外观不决定其性格或活动。

`recipes/campfire.fluid.json` 来自 Pixelbolt 的 MIT 示例，仅改名称后编译。其授权全文保存在 [PIXELBOLT-LICENSE.txt](PIXELBOLT-LICENSE.txt)，公开静态资产目录也附相同授权。Pixelbolt 作为构建工具使用，其源码无须部署到服务器。

图像数据不包含玩家、凭据、AI 对话或运行时数据。网站中的姿势由真实公开回执与状态选择；休息、战斗、种田均不由美术循环自主触发。

v0.11.0 共发布 36 组图像：新增独立农作区背景、三种等级的锄头/水壶及对应图标，人物与配饰、装备图集补齐开垦、维修、升级姿势。大地图的田块已移除；农作区按真实地块状态展示荒地、已开垦、播种、生长和成熟。只有真实公开回执才播放工具动作，不用循环动画代替实际劳作。

v0.13.0 共发布 49 组图像，所有 PNG 合计约 181 KiB。保留原八种人物身份与装备叠层，补充徒手采集、料理、食用三种姿势；九种材料、种子、作物、料理和金币图标；四处拾枝、碎矿、料理与补给设施。设施位置来自服务器生活目录，按场景原生比例放置，不把静态树木当成可采节点。森林采用松树、阔叶树、桦树三种轮廓，营地暖土、森林冷绿、遗迹灰石区分地面，湿田垄仅在服务已浇水的状态使用。

采集循环仅持续真实 `life.gathering` 的有限时间；结束等待服务器确认，取消、暂停、断线时停止。料理与食用是短暂的成功回执姿势，未制造第二条制作倒计时。新增公开目录不包含个人库存、额度或流水；这些只在主人自己的仓库中显示。

v0.14.0 共发布 55 组 PNG，合计 200,564 字节。猎弓、重锤和重型护甲使用与人物同步的 74 帧装备层；三类探索发现拥有静态等待姿态和由真实结算触发的短效果。发现实例位置来自服务器，重叠实例在地图合并计数，选中对象的详情仍独立。装备有实际服务数值，像素造型不推导伤害、射程或冷却。旧人物与素材身份保留。

## v0.19 可复用动作图集规范

以下是当前图集约定；上面的版本记录仅用于说明历史变化。前端显示与交互约束见 [v0.19 UI 契约](../../docs/V019-UI-CONTRACT.md)。

### 文件、方向与命名

- 可编辑源：`recipes/<资源名>.pixel.json`。PNG、atlas 和前端 manifest 一起导出到 `public/pixel-world/`，不得只替换 PNG 而保留旧帧坐标。
- 八种角色仍使用 `wanderer_1` 至 `wanderer_8`；装备、配饰和工具使用既有稳定 ID。新增姿势不重新分配任何角色外观。
- 帧名为 `<动作>_<帧号>`、`<动作>_north_<帧号>`、`<动作>_east_<帧号>`，帧号从 0 开始。动画键还提供 `<动作>_south`，引用基础动作的同一组帧，不额外复制像素。
- 南、北、东为实际绘制方向；西向在显示时镜像东向。身体、配饰、护甲和手持层必须一起镜像，不能只翻人物而留下未翻转的武器。
- 当前人物图集有 17 个基础动作，每个动作 3 个绘制方向、每方向 4 帧，共 204 帧；加南向别名后有 68 个动画键。图集为 8 列，384×1248 像素。源帧数须保持在 Pixelbolt 的 256 帧限制内。
- 新装备和农具应覆盖人物全部动作键。`tests/v019-render.test.js` 检查方向覆盖和每层帧时长一致，避免换装时退回不匹配的待机姿势。

### 尺寸与接触点

| 素材 | 帧尺寸 | 脚底或放置锚点 | 约定 |
| --- | --- | --- | --- |
| 人物、装备、配饰、工具 | 48×48 | (24,43) | 层叠后共用同一位置、缩放、朝向和动作时间 |
| 怪物 | 48×48 | 图集为 (24,43) | 地图显示沿用 43.2 像素的脚底对齐，名牌和血条跟随同一实际位置 |
| 前景地图道具 | 128×128 | (64,120) | 按地图定义中的脚底 y 排序，不按图像左上角排序 |
| 物品、作物、工具图标 | 32×32 | (16,32) | 图标不能代替世界中的实际物品或产量 |

手的位置不是所有帧共用的常量。生成器的 `pose(action, frame)` 返回手坐标、身体升降和步幅；人物与手持层均调用它，实际手部 y 使用相同的身体偏移与上限规则。调整手臂姿势时必须一起重生相关武器、工具和配饰，不能靠浏览器额外平移某件武器修补单帧。

北向手持物绘制在身体后方，其余方向绘制在身体前方；护甲、配饰仍与身体对齐。剑刃、锤头和弓箭在挥击帧按实际方向朝上、下、左或右。走和跑保持相同脚底基准，奔跑使用不同步幅、摆臂与身体升降，不能仅加快播帧。

### 帧时长与服务动作映射

| 动作 | 四帧时长，毫秒 | 循环或选择方式 |
| --- | --- | --- |
| 待机 | 700、180、700、140 | 素材可循环；世界中无实际活动时不强制持续表演 |
| 行走 | 150、150、150、150 | 有有效移动时循环，完整周期 600ms |
| 奔跑 | 105、105、105、105 | 有有效跑动时循环，完整周期 420ms |
| 攻击 | 180、100、140、240 | 图集不循环；运行时按权威阶段选择关键帧 |
| 受击 | 100、100、100、100 | 不循环，仅在真实 `hurt` 有效期间显示 |
| 休息 / 疲劳 | 每帧 500 / 340 | 仅在相应真实公开状态下使用 |
| 其他劳动 | 每帧 150 | 采集限于真实工作计时；一次性成功动作不循环 |

显示时钟约 30Hz，用于位置与时间采样；它不意味着每张图集都以 30 帧每秒播放。身体和装备使用同一个采样时刻。移动速度与体力消耗来自服务规则，不能从图集周期推算。

攻击帧 0 是准备，帧 1 是蓄势，帧 2 是挥击，帧 3 是恢复。当前映射由 `src/pixel-state.js` 的 `actionPose` 负责：

1. `outcome` 尚未返回时，准备期前 45% 使用帧 0，其后使用帧 1；即使已超过预定 `impact_at` 也不自行认定命中。
2. 只有实际 `outcome: hit` 才显示帧 2，持续到 `resolved_at` 后最多 160ms，且不超过恢复区间的 45%；其后为帧 3。
3. `miss` 不播放命中帧；取消或结束退出攻击动作。收到有效 `hurt` 时，受击姿势优先；同时存在的攻击恢复状态仍由服务保存，不根据图片补扣血。
4. 相同 `action_id` 不重新启动动作；重新连接展示当前阶段，不补演历史战斗。超过移动预测上限、失联或暂停时，不在原地持续播放走跑。

### 生成、校验与画面复核

从仓库根目录执行，前一命令成功后再继续下一条：

```sh
node scripts/build-pixel-world.mjs --inspect
npm run build
node deploy/check-pixel-assets.mjs
node --test tests/v019-render.test.js tests/pixel-state.test.js tests/scene-state.test.js tests/render-packet.test.js
npx playwright test tests/browser/motion-camera.spec.js tests/browser/phaser.spec.js --project=accounts
```

`--only=wanderer_3 --inspect` 用于局部素材检查；发布前仍需完整生成和校验。不要手工修改已导出的 atlas 帧坐标。检查器核对图片尺寸、帧边界、动作覆盖、道具锚点和地图可达性，浏览器测试则读取真实 canvas 像素，检查移动、动作阶段、装备及镜头位置。

肉眼复核诊断表 `artifacts/v019-motion-contact.png`：比较四方向的脚底、手柄接触点、奔跑摆臂和四个攻击姿势。再检查实际地图中的前后遮挡、长名字、多人同格和三个目标视口；图集验证通过不能代替渲染检查。

历史基线：v0.19 发布 76 张 PNG。该版本公开素材目录总量为 **4,883,313 字节**，其中 PNG 为 **453,642 字节**、JSON 为 **4,428,591 字节**、授权文件为 1,080 字节；v0.18 相同目录为 1,706,988 字节，增加主要来自多方向帧描述。统计包括完整发布目录，未压缩，不等于浏览器一次加载的网络流量或运行内存。Pixelbolt 只在构建时运行，肥鱼仅提供静态文件。
