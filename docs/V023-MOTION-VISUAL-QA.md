# v0.23.0 动作视觉验收

## 最终结论

**视觉通过，无未解决的视觉发布阻断。** 首轮发现的身体透明缺块及伤害数字遮挡已修复，并重新检查实际浏览器画面。该结论基于源图检查、连续截图及正常墙钟录像，不能由单测通过代替。

这次是**新增动作关键帧，加上连续的重心、倾斜、伸缩与持物变换**。它改善了步态、跑步腾空、受击退让和工具下挥的可读性；并非全骨骼动画，也不表示每台设备都能达到 60 FPS。

## 范围与方法

- 用生产前端构建运行隔离的内存世界，不连接模型，不修改线上世界。
- 人物：两批共八个身份；南、北、东、西四向；步行、奔跑、受击、斧头/镐采集；同时带剑、护甲及外观附件。
- 怪物：三种怪物，四向步行、奔跑、攻击、受击。
- 首轮保留 48 组、336 张截图。修复后复拍同样 48 组，每组保留三个时间点，共 144 张截图；另录制正常墙钟运行的四向步行、奔跑、攻击、受击和采集视频。
- 人工重点复核多纹理同屏、方向切换、身体完整性、持物位置、站姿受击、采集下挥，以及身体与浮字的遮挡关系。
- 固定时间样片是明确标注的渲染 fixture，不作为伤害结算或真实 AI 决策的证明。真实授权动作、取消不产出、路径约束等由 `tests/browser/motion-polish.spec.js` 及相关战斗/移动用例验证。
- 此轮旁观者浏览器没有写请求，没有 JavaScript 页面错误。开始时 fixture 的非逐格长路径被服务端正确过滤，已改为 `recordMovement` 的逐格路径；这不是产品缺陷。

## 修复前后的观察

| 检查项 | 首轮观察 | 修复后观察 |
| --- | --- | --- |
| 同屏多身份与怪物 | 头部、身体、护甲出现矩形或三角形透明缺口；正常墙钟播放也复现 | 修复纹理编号采样后，复查方向与动作中的轮廓完整，未再见同类缺口 |
| DOM 与 Phaser 对照 | DOM 完整，Phaser 缺块，排除 PNG 源图缺损 | 两条路径使用一致的源帧与姿态；Phaser 修复没有依赖删减身份或关闭多纹理 |
| 步行与奔跑 | 旧图支撑过渡不足，奔跑缺少另一侧腾空姿势 | 新 passing 姿势和反侧腾空姿势可见，身体有连续重心变化，步行与奔跑可辨 |
| 受击 | 旧图复用蹲姿；4x 镜头的伤害框遮住身躯 | 使用站姿护胸/后仰；伤害数字位于头顶，按屏幕大小显示，能看到身体反应 |
| 工具采集 | 旧序列挥动后突然使用蹲姿 | 抬工具、下挥、站立收势可辨；身体与工具共用时间采样，斧/镐随手位移动 |
| 四向装备 | 需要检查新副图的握持点及背向遮挡 | 剑、斧、镐未发现明显脱离；背向身体遮挡前侧手位，特别复核了 wanderer_3 的背向工作姿态 |
| 三种怪物 | 同样受到纹理缺块影响 | 史莱姆形变、野猪俯身、石怪抬臂均保持完整轮廓，面向正确 |

修复前的缺块来自 Phaser 多纹理采样路径：插值后的浮点纹理编号直接参与精确比较会落入错误分支。修复在批次着色器中把编号还原为整数后选采样器，仍然保留多纹理批次。伤害数字则改为随镜头逆缩放并抬高位置。

## 实际限制

- 仍是有限关键帧的二维图集。源帧之间可看出姿势切换，不具有逐关节、逐手指的连续变形。
- wanderer_1 背向的左右 passing 差异较弱；这次没有把微弱差异描述成完全自然的骨骼步态。北向被身体遮挡的握持点按腕部位置校准。
- 三时点样片不能保证捕捉到所有短暂受击峰值；部分首帧也可能仍显示新纹理加载前保留的完整旧姿态。完整录像、源帧检查与动作时序测试共同补充这一限制。
- 软件 WebGL 与硬件 GPU 的速度不可混为一谈。性能由独占采样另行记录；渲染器目标频率不是实际 FPS。后续软件后端采用 1x 绘图分辨率，动作、锚点及纹理选择逻辑不变，本视觉结论不构成所有设备的帧率保证。
- 动画只表现已获准的世界状态，不增加 AI 决策、移动距离、命中、采集收益或自动行动。
