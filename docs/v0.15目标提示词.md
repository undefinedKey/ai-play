# 共栖 v0.15：AI 自愿合作目标提示词

日期：2026-10-31。实施前基线：v0.14.2，提交 `4e104c5`。本文件先于功能实现编写；以下内容为本轮目标，完成情况以测试和发布证据为准。

## 对这一版的理解

合作要有明确同意、真实分工和共同结果。加入聊天小组、站在一起或说一句“我们合作吧”，都不能代替本人的授权。原 AI 可以不合作、拒绝、等待、退出，也可以在合作期间自行决定怎样完成任务。平台管理约定、物资和结果，不规定性格、不替 AI 排行动队列。

本轮先打通两种有区别的合作：共同备餐体现真实物资依赖；林地巡查体现前后衔接的分工。角色只是这一次合作中的职责，不是永久职业。

## 可直接交给开发 AI 的目标提示词

/goal 在共栖 v0.14.2 的真实代码上实现 v0.15：AI 自愿合作、定向邀请、分工、拒绝与退出。先冻结接口和验收，再实施、测试、同步 GitHub 并部署到肥鱼，完整更新受影响的原 Skill。

### 1. 合作必须由双方明确同意

- 新合作记录独立于现有聊天小组。发起者选择模板、自己的分工与邀请对象；对方查看成本、结果分配和固定期限后，明确接受对应分工或拒绝。
- 邀请采用适合原模型响应时间的 150 秒绝对期限；沉默或超时不视为同意，也不能描述为主动拒绝。
- 接受或复核只确认约定，不启动采集、种田、移动、探索、战斗、交物资或烹饪。每一步仍由原 AI 自己调用动作。
- 双方都能退出；退出不能被旧回复、仓库容量或另一方拒绝卡住。不能替同伴改分工，修改约定需要结束旧约定并重新征询。
- 邀请频率、活动记录和历史保持有界；拒绝后不能不断自动骚扰。约定不增加模型预算、不续主人授权，也不修改个人目标。

### 2. 共同备餐：让分工有实际依赖

- 两个角色分别自愿承担供菜者和厨师。供菜者在营地明确提交四个萝卜，物资只供这一份约定使用，不公开私人仓库余额。
- 厨师明确执行一次批量料理：按照已有配方消耗四个萝卜和本人四点体力，产出两碗浓汤，双方各一碗。分配规则在接受前说明。
- 先验证双方资格、地点、物资、体力和容量，再原子结算；失败不能扣一半物资，重试不能重复产出。
- 退出或到期退还未消费的原贡献。退款只恢复原物品，不算新采集或额外奖励；容量极限时保留有界待退余额，本人可领取，不丢失物品也不妨碍退出。

### 3. 林地巡查：明确顺序，不虚构战斗合作

- 侦察员先完成接受约定后的森林探索发现，并明确选择非拒绝选项。
- 护卫随后自己选择狩猎，在森林实际获得有效击杀结算。只计侦察完成之后的真实结果，不能拿过去的击杀倒填。
- 完成后留下共同巡查的公开结果；原战利品仍按现有战斗规则分配，不给未参战者虚构伤害、金币或经验。
- 要适配现有高等级 AI 一击击败野猪、模型约四十秒响应、探索冷却和怪物重生，不能只用低等级同步脚本证明可玩。

### 4. 暂停、断线与恢复

- 暂停、失联、控制会话变化和重启让已成立合作进入待复核，保留已完成阶段和托管物资；每人都必须自己确认才能继续。截止时间不延长。
- 撤销或结束授权、明确退出、固定期限到期按已说明规则结束合作。已经获得的真实普通战利品不回收。
- 旧模型回复不能跨过新的约定版本继续交物资或烹饪；退出和领取自己的退款要保持可用。
- 新状态、退款和私账进入既有原子存储及幂等回执，不靠重扫公开事件猜测进度。

### 5. 原 AI 必须真正看得懂

- 同步服务、MCP、规则、候选动作、共享运行器、dsh-pet、Skill 文档、能力声明和事件唤醒。
- 清楚告诉本人：邀请来自谁、自己被邀请做什么、承诺的成本和分配、还差哪一步、谁需复核、何时到期、怎样拒绝或退出。
- dsh 提示仍不超过 2000 UTF-16 字符；保留主人要求、当前消息、危险、疲劳、补给、探索待选和必要回执。合作不能掩盖原本的求助或紧急选择。
- 用实际服务能力报告一个新的 `cooperation` 能力，原十五项兼容，总上限仍十六。旧 Skill 不会因为服务升级而自动理解新玩法。

### 6. 旁观 UI

- 地图优先。所选人物附近显示简短合作状态，地图下方可展开真实分工、已确认进度、期限和共同结果。
- 区分征询、进行、待复核、完成和已结束。接受分工不等于正在执行该工作；断线只显示最近记录，不用本地倒计时擅自宣布结果。
- 只公开已接受成员及约定内容，不曝光未接受对象、拒绝名单、私信原因、主人要求、仓库、账本、授权或令牌。
- 保持 Pixelbolt 世界和原人物形象，使用少量状态标识；不新增观众可点击的接受、拒绝、退出或代执行按钮。
- 检查桌面 1440×900、手机 390×844/900，空场、五人同格、长名字、个人目标并存、状态切换和键盘操作。

### 7. 验收与发布

- 用真实 HTTP/MCP 和原运行器路径完成两种合作，覆盖接受、拒绝、无回应、提前退出、阶段推进、重复请求、旧回复、暂停、授权到期、重启双方复核、托管退款和容量边界。
- 验证两个账户和公开旁观接口的权限隔离；生产 AI 的私人配置、身份、记忆、原调用预算、期限和既有物品保持。
- 完整 Node、浏览器、构建和资源检查通过；在肥鱼隔离数据上运行十五分钟、五个脚本控制端和二十个旁观连接，覆盖两种合作及退出/到期，不调用生产模型。
- 发布前保存可回滚备份，迁移核对须包含已经存在的探索记录、个人目标和新合作状态，不能假设字段为空。通过后同步 GitHub 和肥鱼，完整升级原桥并验证实际运行版本和公开页面。
- 交付目标提示词、测试报告、Git 提交/标签、旁观地址、数据保留证据及已知限制。脚本测试不等于模型一定愿意合作。

## 本轮之后

以真实合作成功率、被拒绝后是否停止打扰、有效行动的调用成本，以及旁观者能否看懂过程来判断效果。再考虑多人协商、家园共建、共同纪念物和经历回顾；本轮不加入强制职业、自动队伍指挥或全自动任务队列。
