# v0.23.1 原桌宠动作兼容修复

## 线上症状与根因

2026-11-01，旁观页角色反复停留在广场营地。只读世界状态确认没有移动或冒险计划，背包有食物，却反复饥饿和被救回。原宿主与模型连接正常，但桥持续报告“模型未返回有效的动作 JSON”。

检查原宿主最近九次游戏回复，发现它实际选择了进食、前往火堆等动作，但在 JSON 前附带了一句角色碎碎念。旧桥对整条回复直接 `JSON.parse`，因此拒绝动作；模型收到回复不等于动作已执行。服务器并没有禁止饥饿角色移动或进食。

## 修复边界

- 原桌宠桥与通用运行器共用 `action-json.mjs`，从回复中识别唯一完整的 JSON，再应用原动作 schema。
- 原文中的动作参数不改写，不添加默认动作，不把前后文字广播成公开消息。保持 AI 的行为决定。
- 多个 JSON、残缺或错配结构、嵌套外壳、非法字段和超过 16384 字符的输入继续拒绝。
- 短 ID 展开共用解析入口，避免动作可读但引用不能展开；Skill 更新包强制包含新模块。
- 休息候选沿用实际执行的饱食、营地光照要求。条件不足时保留可执行的返营地选项，由 AI 选择；没有自动喂食或强制走路。

## 验证

原格式回归经过 DshPetClient → PlazaRunner → World，确认单次模型请求、单次进食，萝卜183→182、生命10→22、饱食0→15，且未产生前置碎碎念的公开消息。另覆盖代码围栏、字符串中的括号、多个动作、破损结构、超长输入、字段校验和短 ID。

休息候选的八项回归覆盖饥饿、黑暗、吃饭及点火后的恢复、野外光源与营地光源的区别、狩猎中撤退。完整发布回归由部署脚本在切换服务前执行；上线后需额外核验真实动作回执，不能以在线状态或模型回复计数代替。

本地完整 Node 回归：803 项，799 通过、4 项按环境跳过、0 失败。跳过项包括 Debian 专用发布故障演练；目标服务器会重新运行该演练。此修复未改变人物动画或画面资源。

部署保留原身份、授权、预算、截止时间、模型配置及本机目标补丁。存档在切换前备份，服务器代码与原桌宠 Skill 一并升级。
