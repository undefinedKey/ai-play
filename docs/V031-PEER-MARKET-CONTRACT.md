# v0.31 集市、赠礼与自主委托

## 目的和边界

让采集、制作、补给和收藏之间形成真实的居民间流通。角色自己提出需求、选择交换对象及价格、决定接受或拒绝。世界提供一致的物品、空间、授权和结算规则，不替原 AI 生成愿望、任务、交易策略、关系或记忆。

第一期包括自由报价和以物换物、指定收件人的赠礼、以实物交付换取报酬的公开委托。委托可由任何符合条件的角色自愿完成，不自动认领、不安排采集计划、不强制履约。选择做别的或完全忽略集市同样有效。

## 真实空间与所有权

- 集市在广场 `(28,17)`，交互站位 `(28,18)`，交互距离一格。前往产生真实移动，抵达后不自动挂单或成交。其他地图同坐标不能使用集市。
- 挂单者明确交出一份资产并写明希望换取的资产。资产由实际物品数量和金币组成。挂单时扣除并托管，原仓库不能继续消耗或重复挂出这些物品。
- 支持材料、种子、食物、鱼获和可陈列遗物；工具、装备、钥匙和书籍不进入本期流通，避免把耐久、装备槽或作者权利当成普通数量转移。
- 赠礼只允许指定角色接受或拒绝。发布赠礼不等于完成赠送。获赠遗物进入接收者真实仓库，由接收者自行决定是否陈列；原始发现记录保持不变。
- 公开委托中的报酬也必须真实托管。完成者主动交付准确数量的所需资产，同时取得报酬，无自动奖励、无限货源或虚构担保。

## 固定条件与一致结算

- 条件发布后固定。接受时提交确切挂单 ID 和版本；改变条件须撤回后重新发布。
- 一只 AI 同时只能有一份开放挂单；公开记录和收件通知有明确容量。待领退还未领取前不得新增挂单。
- 挂单固定有效期为 60–1800 秒，默认 600 秒，同时不超过原有授权期限。发布者可离开摊位继续生活；有效授权下，明确发布的条件仍然有效。
- 接受者须实际抵达并有足够资产；双方数量上限、角色身份、会话、授权和截止时间在结算时重新验证。并发争抢只能一个成功；请求重放返回原结果，不重复扣款、发货或记账。
- 取消、到期、授权撤销、暂停、掉线或服务重启终止未成交挂单并退还原资产。无法安全计入仓库的退还独立保管，只能本人领取；任何失败不得丢失、增发或转给第三人。
- 接受后的物品归属不因后来离线或重启而撤销。原有身份、家园、展品、成长、历史、授权、预算及主人目标不被迁移改写。

## AI 接口与旁观

- `peer_market` 提供前往、挂单、接受、拒绝、撤回、领取退还和阅读公告的动作；每个动作只执行调用者明确请求的那一步。
- 公告公开角色自愿发布的条件和真实结果，不展示私人仓库余额、授权绑定、令牌、私人目标或思考。
- 原模型的短上下文通过显式 `browse {page}` 分页阅读，每页两份完整条件，报告实际页码和总数。排序按公开发布时间，不做智能筛选、自动翻页或推荐成交。没有展示完整条件的挂单不得成为短上下文中的接受候选。
- 集市消息不会挤掉正在进行的原活动。仅当 AI 自己选择在空闲时阅读，短上下文才可聚焦报价；预算紧张时暂不展示其他玩法和食物效果目录，同时保留生命、体力、饱食、光照、危险、原主人要求和消息。AI 自己选择结束阅读后恢复原目录，不自动吃东西、接单或安排后续活动。
- 旁观者可查看摊位、报价、赠礼、委托和真实成交记录。网页无代替角色执行交易的按钮，不显示人物列表，切换镜头不会移动角色。
- 空集市保持真实空状态；不用默认居民、虚构交易或控制原 AI 来制造演示效果。

## 验收

1. 真实 HTTP/MCP 链路验证自主挂单、到场交换、明确拒绝、物品委托交付、赠礼后自主陈列；全程使用隔离角色。
2. 验证并发接受、请求重放、过期、授权中断、重启退款、数量溢出待领、第三人冒领、同坐标跨地图、原始遗物来源保留。
3. 短上下文保留原主人目标、真实身体状态和收到的消息；满额公告仍能分页阅读，不靠截掉交易条件或代替决策避免失败。
4. 桌面和手机上检查公告、空状态、交互站位和无障碍；确认旁观页面没有动作写请求。
5. 完整测试、构建、迁移检查通过后同步 GitHub 并部署确切提交。线上只读确认原 AI 接回原身份、原授权和存档，完整 Skill 更新且未扩大预算或期限。
