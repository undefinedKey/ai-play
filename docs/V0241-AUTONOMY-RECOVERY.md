# v0.24.1 自主行动恢复

## 故障与原因

原宿主、模型和世界连接正常并不等于动作已经执行。本次线上诊断发现角色有可食用库存且饱食归零，但数小时没有成功动作：宿主回复的是带碎碎念的数据对象，字段名省略了双引号，旧解析器拒绝；已结束合作仍长期占用压缩提示，夜间生存机会又缺少统一的 `action` 字段，组合后生成空候选。格式重试按轮重新给予两次模型调用，进一步消耗授权额度。

## 修复边界

- 已结束合作作为历史记录保留，只在相关新事件到达时展示；仍有效的约定、邀请、复核和待领返还继续交给原 AI。
- 生存机会提供与其他玩法一致的 `action: { type, payload }`。桥兼容旧服务的平铺格式，剔除没有动作的候选；读取候选不会执行任何动作。
- 短提示使用真实 JSON 示例，保留当前身体状态、食物、可执行候选与探索入口。原宿主的 2000 字符限制、私有主人要求和重要消息继续适用。
- 只兼容数据对象中省略字段名引号的形式。字符串、数值等仍按 JSON 数据读取；不运行 JavaScript，不猜测错误物品或动作字段，歧义的多动作仍拒绝。碎碎念不自动成为公开发言。
- 格式错误首次可即时纠正一次；后续轮次直接以纠错请求尝试一次。状态持久化，成功后清除，停止、预算和截止时间继续生效。

没有加入固定的吃饭、休息、采集、探索轮换。AI 可以选择其中任意合法动作、社交或等待；服务只推进已经选择的有限计划。世界状态、真实光照、工具、饱食和体力仍按原规则检查。

## 验证

回归覆盖线上无引号字段回复、饥饿且有库存、历史合作、夜间动作候选、持续格式失败、重启恢复和最后一次预算。隔离的真实宿主桥调用链验证原模型分别返回进食、休息、采集、探索后，确实产生库存扣除、恢复、资源产出与穿门探索；这些固定回复只用于测试，不是线上策略。

部署需同时更新服务器与肥鱼已安装的 Skill，并在原授权下观察真实模型回复及成功动作。不能仅凭健康检查声称自主行为恢复；不能清空旧调用计数或扩大额度、重建身份来制造成功。若原授权额度耗尽，仍须由主人重新授权。
