## 肥鱼上的隔离负载

结果见下表。使用独立应用子进程、临时数据库、真实 HTTP 的 5 个脚本控制端和 20 个公开增量 SSE 连接；没有真实模型调用，没有访问正式角色或凭据。脚本选择合法的有限探索/狩猎/休息计划，仅用于测试，产品不会使用它替原 AI 决策。

| 项目 | 实测 |
| --- | --- |
| 环境 | 肥鱼 Debian，2 核，物理内存 1942 MiB，Node v22.23.4 |
| 真实运行时长 | 1800.15 秒 |
| 控制端 / 旁观连接 | 5 / 20，结束时 5 个角色仍活动 |
| 确认执行 / 失败 | 564 个动作 / 0 失败；旁观连接错误 0 |
| 公开 SSE 帧 | 合计 45,200；每观众平均约 10,655 字节/秒 |
| 应用内存 | 峰值 145.91 MiB，结束 139.25 MiB；稳定窗口中位数差 +14.06 MiB |
| 世界 tick | p95 0.80ms，最大 18.37ms，共 5960 次采样 |
| MCP 往返 | p95 97.67ms；含同机 HTTP 与并发控制端开销 |
| 应用 CPU | 合计 54.96 秒 CPU 时间 / 1800.15 秒墙钟 |
| 负载客户端内存 | 峰值 107.16 MiB，与应用分开统计 |
| 有界记录 | 峰值事件 2162 / 3000；动作回执 564 / 1000；客户端帧缓冲峰值 14,701 字符 |
| 判定 | RSS <512 MiB、tick p95 <50ms、无连接失败、记录不超上限均通过；未观察到明显失控增长 |

保留完整 5 秒采样。RSS 比较采用启动稳定后的窗口与最后窗口中位数；一次 30 分钟检查只能说明本配置下的观测结果，不能推断无限运行、无限 AI 或模型服务容量。应用与负载客户端分进程统计，不把客户端内存算成应用内存，也不把远程模型等待当世界 tick 耗时。

## 原宿主验证边界

肥鱼原来的 `main` 桌宠通过本机只读接口确认存在、可访问；本次没有向暂停角色发送 `/chat`、创建替代角色或擅自恢复授权。原宿主连通与真实模型长期活动是不同验证层级；后者需在主人本来允许的活动状态下观察，不能把桥进程 active 当作 AI 已经在玩。

## 保留与兼容

- 原角色、仓库、作物计时、装备、农具、外观、固定授权、预算和接入配置保留；升级新增在场历史字段，缺少旧历史时显示未知，不编造首次入场时间。
- 服务详细 health 仅主人可见；公开页/其他主人的角色投影无 health、原主人目标、预算、凭据或私有库存。
- 旧 calls_used 保留，新请求/回复/本地失败统计从新版已有证据开始；上游没有 usage 时显示未知，不推算账单。
- 本地待处理队列上限 100，服务最多 3000 条事件/10 分钟补取窗口；显示积压、溢出和事件缺口。可靠批次不是无限离线收件箱。
- 新格式锁可证明原进程死亡后回收。旧 PID 文件、损坏/空目录、权限未知的锁保持拒绝；正常停止旧桥后升级。跨机器控制权不等于本机文件锁，仍遵守服务授权。
- 原宿主固定 URL 无自动发现文件时继续原地址；不能猜测新地址或更换 pet。v0.11 的旧绑定首迁仍需原地址验证。
