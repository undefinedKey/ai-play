## 规则、闭环与隐私

- 真实 HTTP/MCP 加注入的游戏时钟验证：工具损坏、材料/金币/种子全零 → 免费休息 → 徒手采集 → 交售/买种子 → 修双工具 → 双田种植浇水收获 → 制作两种料理 → 使用面包 → 继续交易。全程击杀数为零。
- 集成测试使用可控动作验证“能完成”这条路线，不代表真实 AI 必须按此顺序行动。满生命使用浓汤拒绝且不消耗，其他料理效果由规则测试验证。
- 采集开始预扣体力，完成才给一份材料；取消、走动、暂停、召回、控制权转交、授权到期、45 秒失联、房间暂停、重启均中断旧工作。延迟 tick 不补做多轮，采集期间不按闲坐回血。
- 重复动作/完成检查不多扣或多发；失败原子回滚。金币安全整数、交易方向、数量、额度、刷新时间及库存上限均有边界检查。
- 旧数据只新增期初账目；初始物资不重送。旧工具、作物计时、装备、外观和成长保留，额度与冷却不被重启重置。
- 私人账本最多 100 条，累计计数保留；动作回执不复制整本账本。120 笔交易后仍满足上限，回执不存在 ledger 历史。
- 本人/主人可读库存、个人剩余额度和账本；匿名、邻居和跨主人投影排除这三类数据。公开交易事实与规则价格不暴露完整私人明细。
- 原 AI 两种运行方式均理解新动作与真实拒绝；采集中按 ends_at 等待，完成/取消唤醒。dsh-pet 压力测试保持 2000 UTF-16 限制，保留消息、危险、疲劳、食物与取消入口。独立模型每轮上下文剔除完整账本。

## 肥鱼上的真实 30 分钟隔离负载

独立应用子进程、临时数据库、5 个脚本控制端、20 个公开 SSE 观众。五个角色从零库存与损坏工具开始；没有真实模型调用，没有读取或操纵正式角色。服务源码、package 与负载脚本的 SHA-256 与最终候选一致。

| 指标 | 实测 |
| --- | --- |
| 环境 | 肥鱼 Debian，2 核，1942 MiB 内存，Node v22.23.4 |
| 实际墙钟 | 1800.14 秒 |
| 动作 | 1090 个已执行，0 失败 |
| 新玩法累计 | 开始采集 265、修理 20、买入 10、卖出 280、开垦/播种/浇水各 110、收获 100、料理制作 45、补给使用 40 |
| 旁观 | 69,760 帧，0 连接错误；平均每观众约 15,264 字节/秒 |
| 应用 RSS | 峰值 171.84 MiB，结束 160.11 MiB；稳定窗口中位数变化 +26.44 MiB |
| 世界 tick | p95 0.59ms，最大 22.08ms；10,427 次采样 |

各动作门槛按五个角色合计判断，不宣称逐个真实 AI 都作出了全部决定。本次观测没有出现失控增长，但一次 30 分钟测试不能证明无限运行或无限人数。先前本机 90 秒预检只用于准备，不计入这次肥鱼长稳结果；被候选修复中断的第一次负载也不计入最终结果。
