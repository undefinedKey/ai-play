# v0.14 测试与发布前验证

日期：2026-10-31。基线：v0.13.0（`86cfcc1`）。本报告记录 v0.14 的实际验证范围，最终发布提交以 Git 标签和发布记录为准。

## 实现范围

- 森林、遗迹探索产生三类发现，原 AI 通过事件 ID 选择或拒绝；固定 150 秒选择保护，每角色跨区域共享 300 秒发现冷却。
- 猎弓、重锤、重型护甲的射程、攻击间隔、每击体力、防御和移动体力实际参与结算。旧装备兼容，重复计划与换装不刷新攻击冷却。
- AI 可明确设置、替换、确认或取消一条有期限的公开短期目标。四种目标的进度来自设定后的实际结果，不由私有仓库余额、经过时间或客户端自报数字推算。
- UI 提供只读发现详情、真实结果、目标进度和装备取舍；Pixelbolt 增加三类发现物及三件装备，保持原角色形象。
- 共享运行器、dsh-pet、完整 Skill 和能力声明同步到 v0.14.0。公开目标独立于主人私有要求；没有自动代选、自动设置目标或强制活动轮换。

## 验证结果

Windows 完整 Node 测试：**462 项，460 通过、0 失败、2 项条件跳过**。两项分别为按需长时恢复探针和 Linux/Bash 发布演练，均已在对应环境另行通过，见下文。完整日志为 `artifacts/tests-v0.14.0.log`。

已完成的专项：服务相关 139 项通过；真实 HTTP/MCP 三条新路径通过；完整浏览器 57 项通过（约 5 分钟）。不把专项数量与全量测试数量相加作为总数。

真实桥恢复探针另行启用：实际停服 **46,011 ms**，恢复耗时 **15,439 ms**；原 agent/run、授权截止、调用上限保持，`calls_used` 为 **1 → 1**。前端构建、完整版本一致性与发布资源检查通过。

发布故障演练在肥鱼临时隔离目录以无权限的 `nobody` 用户执行，通过三项 Python 测试，其中包括八个 Bash 发布场景：准备失败、桥停止失败、服务停止失败、进程未退出、健康检查失败、迁移失败、Skill 更新失败及成功发布。使用真实 Bash、tar、SQLite、文件移动和恢复检查；Git、服务管理与网络命令为测试替身，不操作生产服务。另验证坏库拒绝、未授权归档成员不提取、田地丢失拒绝，以及不含本机 `data/` 目录时仍可执行。记录为 `artifacts/release-safety-debian-v0.14.0.log`。

测试覆盖：

1. 三类发现的七种选择、拒绝、满状态、体力不足、库存溢出、错误 ID、重复请求、迟到移动、150 秒到期、300 秒跨区域冷却。
2. 暂停、召回、转交、授权过期、失联、房间暂停与重启。中断没有离线收益；目标必须由原 AI 明确复核且不延长截止。
3. 三格射程实际攻击及分奖、重锤与重甲的真实间隔和体力、疲劳只折算一次、安全区禁射、冷却持久化。
4. 目标不继承既有库存，失败和旧回执不推进，完成不发额外奖励，不自动开始下一计划。公开投影不含主人要求、内部来源、私人仓库、账本和凭据。
5. 原桥的动作校验、能力兼容、有限等待、消息保留、未知回执查询、预算预留与 2000 UTF-16 字符提示边界。
6. 桌面 1440×900、手机 390×844/900，空场、五人同格、长名字、恶意 HTML 字面文本、同时发现、公开目标、断线与暂停；观众只有只读操作。

## 发布核对与保留项

发布按准确 Git 提交构建，保留私有数据备份与旧代码。准备检查期间保持原桥在线，只在切换和迁移验证时短暂停桥。验证失败先恢复代码与数据，再恢复原桥；完整 Skill 更新保留本地配置和两处既有目标扩展。

生产身份、地块数量与时间、仓库、工具、装备、外观、成长、账本、原授权、调用上限及截止时间逐项核对；不重置调用数。数据库完整性必须实际返回 `ok`。部署后的服务/Skill 版本、原宿主连接、实际能力、配置摘要及公开页面另作在线核对，不把本报告的隔离测试当作已上线证明。

验证原 AI 自主性的范围有限：脚本测试确认“可以选择且规则正确”，不证明真实模型长期偏好或每次都会使用新玩法。具体目标和行动仍由原 AI 选择。单房间仍限五个活动角色；未增加职业、公会、自动队列、碰撞寻路或外部视频服务。
