# v0.19 走跑、动作与旁观镜头契约

本期产品任务是让旁观者看懂原 AI 正在做什么。页面以共享世界为主体，保留已有暖色村落与冷色林地，不增加人物名单。主要操作为地图点选、跟随、拖动、缩放、复位、全屏和可关闭音效；全部只改变观看方式。参考为仓库 v0.18 的真实地图与像素素材，升级保持身份及场景辨识，不重画另一套世界。

## 可检查的层次与布局

- 地图优先；视图切换与镜头工具紧邻地图。公开详情与历史维持按需查看，不占据地图中央。
- 目标视口：1440×900、390×844、390×900。地图等比例，工具可换行；触控控件至少 40×40，键盘可点选人物和移动镜头，焦点可见。
- 手动拖动/方向键停止跟随；跟随对象跨场景时结束跟随并明确所在地，旁观者切页不移动 AI。
- 人物、装备、名字、血条、点击区域及镜头使用同一服务时钟采样的位置。气泡根据实际角色矩形定位。禁止镜头先跳终点。
- 客户端只读取权威移动与动作阶段，不决定伤害、体力或新目标。网络断开冻结位置及动作；恢复展示当前事实，不补演旧动作或声音。
- 四方向待机、走、跑、攻击、受击与劳动共用身体/装备/工具锚点；跑有独立步态。攻击按准备、命中、恢复的实际阶段选帧。受击仅对应真实命中。
- 绘制与服务模拟分离。共用低成本显示时钟，隐藏页面停动画；减少动态效果关闭连续补间和装饰，保留可读的当前事实。

## 渲染证据

必须检查真实画布像素与截图，包括多方向走跑、攻击各阶段、装备接触点、遮挡、名字与气泡、长名字多人拥挤、触控/键盘镜头、全屏、断线与减少动态效果。对三个视口保存截图，执行自动无障碍与人工图像复核。记录至 artifacts/v019-ui-evidence.json，并执行前端设计技能的 check-evidence.js。检查器通过仅说明证据记录完整，不替代实际渲染检查。

## 图集与动作扩展规范

人物、服装、手持装备和工具均为 48×48 帧，脚底锚点为 (24,43)，朝北时手持物在身体后方，其他朝向在身体前方。动作名称采用 `walk`、`run`、`attack` 等基础名；`_south` 复用基础动画的帧，`_north` 和 `_east` 是独立姿态，西向镜像东向。新增装备必须覆盖身体全部动作，并保持同一动作的帧时长一致。

攻击四个关键姿态依次为准备、蓄势、挥击、恢复；客户端以权威 `action` 的时间和结果选帧，尚无结算结果时停留在蓄势姿势，`miss` 跳过命中姿态，`hurt` 只由真实受击字段触发。姿态时间不是第二套伤害计算。奔跑有更大腿部幅度、身体升降和摆臂，速度与消耗仍来自服务端。

素材源为 `art/pixel-world/recipes`，生成器为 `scripts/build-pixel-world.mjs`；运行 `node scripts/build-pixel-world.mjs` 会通过固定提交的 Pixelbolt 验证并导出图集。源动作帧总数不超过工具的 256 帧上限；方向别名不复制像素。用 `node deploy/check-pixel-assets.mjs` 校验发布目录及构建目录，服务器仅提供导出的静态文件。

共享显示时钟约 30Hz，服务端位置广播与模拟独立。显示采样使用 `shared/motion.js`，只允许在最后实际位置时间后预测最多 250ms；超过界限时停止步态。音效默认关闭，手势开启后只播放新鲜、同场景、已结算事件；初次加载、切图和重连建立静默基线。
