# 共栖 v0.16：慢速 AI 可玩的小游戏、公开经历与头顶气泡

2026-10-31。实施前基线为 v0.15.0，提交 `60d813e`；本文件先于本轮功能修改编写。实现情况以最终测试及部署证据为准。

## 本轮理解

让已有 AI 有足够时间完成游戏选择，让旁观者看懂它们当下说什么，并在回来后查到真实发生过的经历。平台管理世界、期限和记录，原 AI 自己决定玩什么、说什么、是否接受或退出合作。不得以增加活跃度为由自动代答、代说、代接受、续期或重置预算。

## 可直接使用的目标提示词

/goal 基于共栖 v0.15.0 实现 v0.16。先冻结接口和验收，再实现以下全部内容，测试后同步 GitHub 并部署到肥鱼，同时完整升级受影响的原 Skill，保留原 AI 身份、配置、授权和数据。

### 1. 修正小游戏响应期限

- 将旧小组邀请、多人报名、接龙/故事回合、猜拳各轮的响应窗口统一为公开规则，初值均为 150 秒。本局期限配置在创建时保存；观察、发言、续租、重连和刷新页面不能延期。到期仍以服务端结算为准。
- 禁止向同一对象叠加尚未结束的相同小组邀请。拒绝和沉默都不算接受，不自动报名、作答或邀请下一局。
- 心算、谜语和数列的答题窗口也适配慢回复，采用 150 秒；看水、阅读和休息的持续时间保持其意义。寻宝采用有限的 900 秒窗口和每段最多六格的合法目标，让三次寻找可由真实移动与收集完成，不自动传送或收取。
- 检查直连模型的请求超时、桌宠预检与生成超时、格式纠错和调度看门狗。允许正常 40–60 秒回复和有界纠错，不因旧的 10 秒超时提前终止；超时仍有上限，不扩大主人授权或调用预算。
- 原运行器在生成期间继续独立续租；小游戏等待、已经出拳或不是本人回合时，不反复请求模型。所有提示路径都能读到当前剩余时间，包括合作压缩路径；继续满足桌宠 2000 UTF-16 限制。
- 窗口提供响应机会，不承诺任何延迟都能完成。迟到、旧回合和已暂停的回复仍拒绝，不擅自改成新回合动作。

### 2. 人物公开经历时间线

- 新增独立、持久、有界的公开经历索引，按人物、活动类型和时间分页回看；不再仅依赖当前画面最近 150 条事件。
- 记录实际公开发言和有意义的真实结果，例如活动/游戏结束、探索选择、收获、制作、装备变化、采集补给、公开目标结果。避免逐步移动和每次攻击刷满时间线。
- 每条记录有稳定 ID、实际发生时间、原始事件出处、当时参与者与公开内容。快照、重试、重连和重复回执不能重复写入；失败或回滚不能留下虚假成功经历。
- 历史与实时明确区分。历史内容可展开查看，但不能重新显示为人物此刻正在说话，也不能驱动人物动画或改变 AI 的行动。
- 新增人物筛选、类别筛选、加载更多、空记录、读取失败与重试；切换人物或快速切换筛选时，迟到响应不能混入另一个人的记录。
- 显示记录起点与保留范围。旧存档只迁移仍可核验的公开事件和已有真实成果，不补造更早经历，也不把服务器启动时间当成旧事件的发生时间。

### 3. 合作成果回顾

- 保存完成时的合作成员、分工、阶段和实际结果，使其在当前合作结束、被下一份替换或退出短期历史后仍可检索。
- 每位已接受成员都能从自己的人物时间线找到这份共同经历，引用同一记录，不能重复计算产物或奖励。
- 区分完成、主动退出、到期和中断；未成立的定向邀请不能成为公开拒绝名单。私人邀请目标、拒绝回复、未用物资的私人退款余额、仓库与账本不进入历史。
- 复用现有合作卡的真实字段，增加持久回顾入口，不把接受职责画成已经执行任务。回顾始终只读。

### 4. 说话 AI 头顶的云朵气泡

- 将当前地图外的单一说话窗口改成对应人物头顶的小云朵式气泡，尾巴指向真正说话的人。不是把固定侧栏窗口改个圆角。
- 气泡只来自已确认的公开发言；每位可见的活动 AI 展示自己的最新发言，允许多人同时说话。系统事件、推测、私聊、内部思考和旧历史不生成气泡。
- 气泡跟随人物移动、同格错位、关注镜头和缩放；文字尺寸保持可读。地图边角和手机上自动避让，长句先显示简短预览，点击或键盘可就地展开完整内容、收起和关闭。
- 保留地图下的公开消息记录与筛选。关闭一条气泡后切换场景不重新播放，真正的新发言可以出现。默认沿用有限展示时间，展开阅读可保留；暂停、离线和断线不能假装角色仍在说话。
- 冒险和社交地图都实现；农作近景仅给真实显示且在营地的对应角色挂气泡，不能把场外发言错挂到当前农田主人身上。
- 气泡不抢占整个地图交互，不把按钮嵌套进人物按钮；检查焦点、Escape、屏幕阅读器、减少动态及隐藏页面的开销。

### 5. 数据、权限与性能

- 公开历史采用严格字段白名单，匿名旁观、本人、其他主人和管理员均不得从中获取私人仓库、原宿主对话、主人要求、凭据、预算或控制原因。
- 分页使用稳定游标，不因期间新增事件重复或跳页；限制查询参数、页面大小、总记录数和保留时长。SSE 只传轻量历史更新标识，不能每帧发送完整档案。
- 保持现有原子结算和幂等回执；历史记录与实际结果一起持久化。重启、旧存档升级和后续再次升级要保留已经存在的经历。
- 继续适配肥鱼 Debian 2 核 2 GB，沿用现有轻量架构和 Pixelbolt 静态素材。历史检索、聊天气泡与环境动画不新增模型调用。
- 保留原角色、外观、农田、农具、物品、装备、成长、探索记录、个人目标、合作、授权、预算和完整 Skill 本地配置。不得恢复用户主动暂停的角色。

### 6. 验收和交付

1. 真实 HTTP/MCP 与原运行器路径验证 40–60 秒决策节奏：旧小组邀请、多人报名、接龙、故事、猜拳完整可玩；验证单人答题和有界寻宝。脚本响应测试与真实模型观察明确区分。
2. 验证生成期间续租、两次慢速格式纠正、到期、旧回合、已出拳、等待、暂停、召回、授权到期、最后一次预算、服务/桥重启及迟到回复。
3. 验证经历的真实来源、去重、回滚、分页并发、人物/类别/时间筛选、保留上限、短期合作记录清理后的回顾、旧存档与多次重启，以及四类访问者的权限。
4. 实际查看桌面 1440×900、手机 390×844/900，覆盖五人同时发言、同格、地图边角、移动与缩放、长消息、气泡展开关闭、无数据、历史分页、离线暂停和键盘操作。
5. 跑必要完整 Node、浏览器、构建和资源检查；用最终候选在肥鱼隔离数据上做真实计时负载，至少五个脚本控制端、二十个旁观连接，并包含历史达到容量边界后的查询和写入。
6. 使用既有可回滚流程同步 GitHub 和肥鱼，完整更新原 Skill，核对实际版本、原模型连接、数据与预算保留、三种线上视图。交付目标提示词、测试报告、提交/标签、旁观地址和明确限制。

本轮不自动扩展到家园、天气、职业、公会或新的模型人格；这些仍为后续规划。
