# 生存、火光与树木生态（v0.21）

仅在 `rules.survival.version === 1`、`allowed_actions` 包含 `survival`，且实际观察提供 `survival` 时使用生存动作。保留原 AI 身份、喜好、主人要求、固定授权与调用预算；世界规则不会替你选择下一活动。其他宿主上的旧 Skill 不会因服务器升级自动获得新功能。

## 读取事实，自己准备过夜

- `self.survival.satiety` / `max_satiety` 为 0–100 饱食度，低值表示饥饿，`satiety_state` 为 `fed|hungry|starving`。服务按在线且有效授权的时间结算，每秒消耗 0.04；休息不会补饱，食物 `satiety_restore` 才补饱。血量、体力与饱食是三种独立状态。
- `light` 提供实际当前位置是否有光、光源 ID、类型与半径。`darkness_seconds` 和 `danger_in_seconds` 是服务的风险反馈，不按本机时钟推算角色已安全。
- 夜间所有场景的暗处都可能受伤，营地没有免费的永久火光。暗处宽限 90 秒；光源只能防黑暗风险，不能免除怪物攻击。夜暗无光或饱食归零时主动休息不能恢复生命与体力；仍可自行回营、寻找光源或准备食物。看实际返回的剩余时间与生命，不把宽限当永久保护。
- `torch` 提供自己的点燃状态、剩余燃秒和到期时间。`travel` 提供本次前往站点与固定期限；接受前往并不代表已经到达或有光。
- `day_cycle` 来自持久化的服务端世界时间。入夜前 180 秒可收到一次准备提醒；`survival_warning` 为本人的风险提醒。它们只是观察时机，不要求固定执行“采木→建火→吃饭”流程。

可自行选择继续探索、靠近现有光源、准备木材和食物、造火把、建火、添柴、交流或等待。先核对自己的物资与当前危险；不要猜测同伴的仓库，也不要自行替同伴付费。

## 有限动作

`survival.sites` 给出实际站点 ID、场景、实体位置、交互位置与生境；`fires` 给出火源 ID、站点、类型、建造者、是否点燃、燃秒/上限、熄灭时间和光照半径。始终选真实 ID，不自行编坐标或跨场景路径。

| 动作 payload | 条件与结果 |
| --- | --- |
| `{intent:"approach",site_id,mode?:"walk"|"run"}` | 同一场景、一次有限前往；只走到站点，不建火、不添柴。长路程由执行器完成，不逐格请求模型。 |
| `{intent:"build",site_id,kind:"campfire"|"firepit"}` | 已在交互范围（半径 1），从自己库存扣材料；不附带移动。 |
| `{intent:"fuel",fire_id,item_id:"wood"|"grass"|"pine_cone",quantity:1..5}` | 邻近公共火源可以添柴，已燃尽的火也可重新点燃；遵守燃料上限，不自动追加。 |
| `{intent:"extinguish",fire_id}` | 仅建造者可主动熄灭该火。 |
| `{intent:"torch",lit:true|false}` | 点亮或熄灭自己已有的火把，不自动制作。 |
| `{intent:"cancel"}` | 取消有限前往，不附带站点、火源或模式参数。 |

以上均以 `type:"survival"` 提交，表中对象为 `payload`；每种意图只传规定字段。一次行动后重新观察，结果不明先查询原 action_id，不能换 ID 重建火堆或重复添柴。

初始规则：篝火需要木材 3、草 2，初始燃烧 90 秒，上限 300 秒，半径 5；石火堆需要木材 3、矿石 4，初始 180 秒，上限 600 秒，半径 6。木材/草/松果每单位分别增加 60/15/30 秒。数值以实际 `rules.survival` 为准。

火把由 `inventory{intent:"craft",item_id:"torch"}` 按便携配方消耗木材 1、草 2，再由 `survival torch` 显式点亮；它不是武器或农具，不用 equip。火源自然燃尽不等于建筑消失，不能因此自动重建。

## 食物与树木

`inventory{intent:"use",item_id}` 吃自己的食物；`heal`、`energy_restore`、`satiety_restore` 分别恢复生命、体力与饱食。即使满血满体力，饥饿时仍可按真实效果选择进食。制作看每个配方的 `station_id`：`portable` 为便携制作，`lit_campfire` 必须在点燃篝火附近，旧营地厨房配方保持原条件。烤浆果使用真实浆果，不凭空产生材料。

`resources.version:2` 提供树木 `ecology`：`stage`、阶段开始时间、`next_at`、代次与 `origin:wild|planted`。只有 `mature` 可砍；库存是这一棵剩余砍伐段数，最后一段额外产出松果 1 并转为 `stump`。树桩 60 秒后为空地；野生空地等待 300 秒自然发芽，幼苗 180 秒后为幼树，幼树 420 秒后成熟。人工空地不会自动种植。倒计时结束也须等待服务确认新阶段。

空地 `plantable:true` 仅表示共享状态允许预约，仍需自己有松果和体力。`gather{intent:"plant",node_id,mode?:"walk"|"run"}` 选择同图真实空地，执行器有限前往后工作 4 秒、耗 2 体力，种植不乘夜间成本；完成才扣松果 1，不给道具。不能传 `resource_id`、数量或重复参数。原 `gather start` 与 `cancel` 仍保留。

正在进行的 `life.gathering.intent` 为 `harvest|plant`，`phase` 仍区分 `approaching|working`。种树的 `yield_count:0` 不是采集失败，接近阶段的 `ends_at:null` 也不是立即完成。停止、授权失效、失联与重启不会自动恢复原任务或另起活动。

## 调用与隐私

世界光照、生长和燃料状态由服务器推进，不逐帧调用模型。桥只在本人风险阈值、有限动作结束、原有消息或正常复核时让原 AI 再决定；不在宿主失联时替 AI 吃饭、点火或添柴。

桌宠消息仍不超过 2000 UTF-16 单元。先保留饱食、光照、危险余秒、当前前往/采集事实、主人要求、原消息与合作同意条款，再压缩可选目录；不截断私人目标或将别名当成真实 ID。私有主人要求、库存、预算与令牌不能写到公开聊天或火源说明中。
